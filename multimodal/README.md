# dsh-multimodal —— 模型多模态开关

在**输入框的模型选择器左边**加一个「图片」勾选框，给当前的**自定义模型**（走 `llm-pi-ai`
手写路由）开关「是否支持图片输入」。网关无法反向探测一个模型到底能不能吃图，所以由你按
模型自行判断：勾上即声明该模型 `input: [text, image]`，不勾则 `text-only`。

浏览器半边 + 一个只读 API，超轻量。

## 功能

- **入口**：输入框模型选择器左侧多一个「图片」勾选框。
- **按模型记忆**：勾选状态按模型持久化，切换模型自动带出各自之前的勾选，不互相串。
- **声明能力**：勾上 → 该模型允许图片输入；不勾 → 文本输入。判断标准是「这个模型你到底
  想不想让它看图」，不是网关探测（网关做不到）。
- **跨会话一致**：状态缓存在前端共享（同一会话/重挂载复用），避免重复请求、保证勾选框与
  实际声明的能力一致。

## 使用

1. 装上、重启服务、进设置/输入框打开一个自定义模型。
2. 在模型选择器左边勾上「图片」就允许它接收图片，去掉则只收文本。
3. 切换模型，各自的勾选自动带出。

## 实现要点

- 后端只暴露一个只读 API（`GET /api/model.multimodal`），返回当前各路由的多模态声明和
  默认模型；勾选结果本质上对应 dsh 模型配置里的能力声明。
- 前端共享缓存（`window.__dshMultimodal`）：多个入口重挂载时复用 routes + 默认模型，
  保证状态一致、少发请求。
- 只影响**自定义模型**的路由（llm-pi-ai 之类）；官方/托管模型不受影响。

## 数据 / 依赖

- 状态按模型持久化（跟随模型配置存在），插件本身不改写你的模型定义，只做读取 + 展示 + 勾选。
- 浏览器半边用 React；后端是 host 的极简只读接口。

## 安装（标准 npm bundle）

```bash
python3 ~/.dsh/skills/dsh-plugin-install/scripts/install_plugin.py ./multimodal
# 或：dsh plugin --profile web add <multimodal 目录>
```

装完**菜单 → 重启服务**生效。

## 已知边界

- “是否支持图片”由你手动勾选决定，dsh 不会替你探测——这是插件的前提（网关探测不了）。
- 只对自定义（手写路由）模型生效；想给不同模型不同能力，就在各自模型上分别勾。
